# Competitive Research: 自托管 AI 互动小说平台（WHnovel）

- **日期**：2026-07-31
- **模式**：Standard（6 个核心竞品 + 相邻/中文市场扫描，共 11 个产品条目，30 条证据，均为一手来源）
- **决策**：WHnovel 的差异化楔子 = **互动小说的游戏化框架（选故事→聊→剧情推进）+ 自带模型的自托管**。竞品生态里没有任何产品占据"聊天式互动小说"这个位置：SillyTavern/RisuAI/Agnai 是"角色聊天前端"（没有故事层），AI Dungeon 是"云端冒险游戏"（无自托管、订阅制），Character.AI/星野是"情感陪伴聊天"（中心化、封闭），NovelAI/Sudowrite 是"写作工作台"（作者创作而非游玩）。README 与路线图都应围绕这个楔子。

## Executive Conclusion

**定位结论**：WHnovel 应把自己讲成一个"**聊天式的互动小说游戏平台**"——用户买的故事是"游戏"而不是"工具"，入口是"选一个故事、跟 AI 聊着聊着把剧情推进了"（[E14] AI Dungeon 证明了这个品类的吸引力：开放式 AI 冒险；[E28] 星野证明中文用户对"AI 推进开放剧情"有强需求）。

**最强威胁**：
1. **SillyTavern**（[E1]，31.4k stars）：体量最大、功能最全的开源前端，但它没有故事层——没有剧情时间线、没有两段式结构输出、没有"故事"这个一等公民，只有角色聊天（[E3][E2]）。它的用户"什么都折腾过"，恰恰是 WHnovel"故事即产品"最可能转化的受众。
2. **星野/Talkie**（[E28][E29]）：中文市场头部，教育了"AI 角色聊天"习惯，但是封闭 App、情感陪伴导向、无 Web 版；其"开放剧情"只停留在宣传语，没有叙事结构支撑——WHnovel 的剧情标签/时间线/结构化输出正好补上这一层。
3. **Character.AI**（[E20]）：2026 年正在用 Lorebook（世界设定库）和记忆系统向"持续世界"补能力，证明"世界观一致性"是这一品类的刚需，WHnovel 需要把它做成差异化的产品能力而非跟随。

**楔子压力测试**：为什么更强对手没有占据"聊天式互动小说"？
- SillyTavern 的路线是"给 power user 最大自由度"（[E2]），它的用户要的是调参和控制，不是被故事框架约束——所以它永远不会有"故事"层；
- 星野的路线是情感陪伴社交（[E28]），用户要的是"和角色谈恋爱"，不是"推进一个故事"；
- AI Dungeon 有故事框架但走中心化订阅（[E15]），模型和内容都被平台锁定；
- 因此"**故事即产品 + 模型自带 + 自托管**"是真实存在的空位，且对 WHnovel 的用户（有 API Key 的 AI 玩家、想收藏自己剧情的读者）可被直接感知。

**三类不做的（non-goals）**：不做多用户社交社区（Agnai 路线，[E11]）、不做情感陪伴（星野路线，[E28]）、不做商业云端托管（成本与合规风险，且违反自托管卖点）。

## Current Product Baseline

已交付能力（来自本地 README、代码与开发记录）：

- 流式聊天：SSE 实时输出，打字指示器 + 智能跟随滚动
- 两段式输出：先推正文，再异步回写结构化尾部（状态、标签、高亮词）——**这是竞品生态里没有的产品机制**，是本项目"故事层"的核心
- 剧情时间线：点标签跳转对应段落
- 存档管理：创建、导出 JSON、导入、行内重命名
- AI 图片生成：封面 + 聊天插图共用可配置图片模型
- 管理面板：模型配置、提示词编辑、存档选项
- 移动端适配：虚拟键盘偏移、44px 触控区、刘海屏安全区
- 技术栈：Vue 3 + Vite + TS + Pinia + Element Plus / FastAPI + SQLAlchemy + SQLite / OpenAI 兼容 API（聊天 + 图片）/ SSE
- 质量基线：后端 Ruff + pytest、前端 ESLint + Prettier + vitest + 类型检查，CI 全绿合入

**本地基线假设（尚未验证）**：多模型切换、长对话一致性、剧情状态的持久化程度（目前标签是输出产物，还不是可读写的剧情状态库）。

## Cross-Market Patterns

**表内筹码（table stakes）**：流式输出、多模型接入（OpenAI 兼容已是事实标准）、角色/世界观设定管理、记忆与上下文管理、移动端可用。缺这些没人用。

**可感知的差异化（WHnovel 独占或领先）**：
- **故事即产品**：剧情时间线 + 两段式结构化输出（状态/标签/高亮），竞品生态中无同类（[E3][E8] 只有聊天，[E14] 有游戏无结构）
- **模型自带 + 自托管**：SillyTavern 有自托管但无故事层；星野/Character.AI 有聊天但封闭（[E28][E18]）
- **中文叙事原生**：星野之外的中文互动小说供给薄弱（[E26][E27] 都是写作工具向）——注意 NovelAI 已在用中文开源底座（[E24]），中文模型生态成熟，WHnovel 的 OpenAI 兼容接入正好吃到红利

**采用阻断性缺口（adoption blockers）**：
1. **缺少截图/演示**：README 无图无动图，repo 首页无法传达"这是什么"——对小白用户是致命伤
2. **剧情一致性无保证**：长对话后"离题回复/人设漂移"是全行业抱怨（[E13][E19][E20]），WHnovel 目前没有剧情状态持久化
3. **角色卡生态缺失**：SillyTavern 的数万张角色卡是现成内容库，不兼容等于放弃最大内容供给

**Non-goals（明确不做）**：多用户社交社区（[E11] 反向）、情感陪伴聊天（[E28] 反向）、云端托管商业版（[E15][E18] 反向）、AGPL 类传染许可的照搬（[E1][E27] 提示生态约束）。

## Prioritized Roadmap

### P0 — 立即可做，改 README 与数据模型
- **R1**：重写 README，以"聊天式互动小说游戏"为唯一主线，配截图/GIF、对比表、快速开始（[E14][E2][E7][E28]）。验收：首屏 10 秒传达定位，repo 有图、有对比、有引导。
- **R2**：剧情标签升级为**可读写的剧情状态数据库**（世界线/人物线/感情线，参考 [E26][E27]；注入正文生成，借鉴 [E19][E20] 的记忆/世界观思路）。验收：50 轮对话抽查 5 个故事，角色名/关系/已发生事件无前后矛盾。

### P1 — 借生态流量、补叙事闭环
- **R3**：支持导入 Character Card v2/v3（[E1][E3]）。验收：角色卡 JSON 导入后设定与示例对话正确生效，损坏文件返明确错误（本项目已有存档导入校验经验可直接复用）。
- **R4**：剧情分支/重开——时间线任意节点可重新选择（[E14][E15][E27]）。验收：分支存档互不影响，切换后上下文正确。

### P2 — 长线留存与传播
- **R5**：长对话自动摘要记忆（[E16][E19][E13]）。验收：超上下文后早期事件仍可被新回合引用，摘要可查看/编辑/关闭。
- **R6**：会话导出可回放 HTML + 公开示例故事库（[E28][E14]）。验收：一键导出离线可读回放，新用户 3 步开始玩。
